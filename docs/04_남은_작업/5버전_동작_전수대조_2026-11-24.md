# Zabbix 5 → 7 커스텀 기능 동작 대조

2026-11-24 · 작업 소스 `4bb9821` · 로컬 Zabbix 7.0.26 / PostgreSQL

**Windows 패치 점검 대상, 성능 추세 그래프와 CSV의 대상, CPU/Memory 추출 파일의 행 구성**을 먼저 맞출 필요가 있다. 셋 다 화면은 열리지만 같은 업무 조건에서 보고서에 들어가는 서버나 수집값이 달라진다.

## 확인 범위

[7버전 모듈 등록표](../../ui/modules/dmove/manifest.json)의 23개 액션을 기준으로 컨트롤러, 서비스, 뷰, 설정 및 공용 필터를 살폈다. 5버전 근거는 [5버전 소스](../../v5_restored/src), [11월 23일 화면 기록](../../v5_restored/screens_new.md), [그 이전 화면 기록](../../v5_restored/screens_old.md)이다. 판독이 끊긴 구간이나 받지 못한 뷰는 확인된 동작의 근거에서 제외했다.

- 로컬 관리자 계정으로 목록 10개의 제목과 오류 상자, CSV 다운로드 7개의 응답, 조회 팝업 4종(Agent, 기준설정, CPU·Memory Top 10, 패치 상세)의 JSON을 확인했다. 파일 응답만으로 내부 값까지 일치한다고 판정하지 않았다.
- 성능 추세는 기존 데이터셋이 없는 테스트 계정에서 패턴을 적용해 SVG와 CSV 응답을 받았다. 종료 후 테스트 데이터셋 프로파일이 다시 0건인지 확인했다.
- 저장 액션 2개(Agent 상태, 사용자 기준값)는 입력 검증·권한·저장 키·DB 쓰기 코드를 대조했다. 운영 이력 추가나 실제 사용자 기준 변경은 시험 범위 밖이다.
- 고객의 5버전 실행 DB, 당시 보고서 원본 파일, 동일 시점의 7버전 DB 쌍은 확보되지 않았다. 아래의 로컬 건수와 조건 예시는 고객 운영 건수를 뜻하지 않는다.

## 그 밖의 화면과 의도한 개선

## 기존 결정과 추가로 확인한 차이

검토 중 추가된 [화면별 차이 목록](./5버전_차이_점검.md)은 문구·색·정렬·필터 초기화 등 작은 차이까지 기록한다. 해당 목록에는 **Peak 초기 심각도를 전체로 두는 것이 기존 결정**으로 적혀 있다. 따라서 위 표의 기본값 복원은 5버전과의 호환성을 우선할 경우의 제안이다. 기존 결정을 유지하면 전체를 기본값으로 두고 검수 기대값에도 이를 명시한다.

다음 네 가지도 운영 결과 해석에 영향을 준다.

- **SW 인벤토리의 ITSM 장애 처리.** 미연동 때도 조회할 수 있게 만든 7버전은 Zabbix 호스트를 ITSM 행으로 대체한다. 이때 미등록 자산은 모집단에서 빠지고 대체 행은 설치 상태로 보인다. 화면에 경고가 있지만 이 조건의 CSV를 설치율 집계에 쓰면 잘못된 결론이 나온다. 운영에서는 미연동 결과에 출처를 표시하거나 이 상태의 내보내기를 구분하는 편이 안전하다. [5버전 ITSM 조회](../../v5_restored/src/CHyundaiItms.php) · [7버전 대체 데이터](../../ui/modules/dmove/includes/SwInventoryService.php)
- **저사용·고사용의 예외 날짜와 키.** 평일의 업무시간 샘플이 하나도 없는 날에는 7버전의 일평균 NULL 제외 조건이 그날의 야간 Peak까지 제외한다. 다른 평일의 업무시간 평균이 있어도 기간 Peak가 달라질 수 있다. 또 5버전 유닉스 CPU 키에서 확인되는 `|awk` 앞부분까지 일치시켰던 조건이 7버전에서는 로그 파일명까지만 일치하면 된다. 같은 파일을 가공하는 다른 지표가 있는 서버는 잘못 분류될 수 있다. [5버전 집계](../../v5_restored/src/CHyundaiCPU.php) · [7버전 집계](../../ui/modules/dmove/includes/ServerUsageService.php) · [키 설정](../../ui/modules/dmove/conf/serverusage.conf.php)
- **CSV를 다시 읽는 프로그램.** CPU/Memory 5버전 실행 경로는 PostgreSQL COPY의 열 이름과 헤더를 쓰고 출력 전체를 줄 단위로 나눴다. 7버전은 UTF-8 BOM, 대문자 헤더, 각 파일의 반복 헤더, 다른 파일명을 쓴다. Excel에서 열기 쉬워졌지만 기존 파일을 이어 붙이거나 헤더명을 정확히 비교하는 작업은 영향을 받는다. 반복 헤더 유지 여부는 소비 프로그램에 실제 파일을 넣어 결정한다. [5버전 파일 생성](../../v5_restored/src/export_csv.sh) · [7버전 파일 생성](../../ui/modules/dmove/includes/UsageExportService.php)
- **계정 조회 권한과 서버 주소.** 장기 미접속 계정의 5버전 컨트롤러는 Super admin을 요구했고 7버전은 유저 화면 권한을 검사한다. 실제 고객 역할에서 누가 열 수 있는지 확인한다. 서버 시간 확인도 DNS로 접속하는 호스트에서 5버전이 DNS명을 쓰던 자리에 7버전 공용 함수가 IP를 표시할 수 있다. ## 운영 데이터에서 필요한 최종 대조

1. Windows 인벤토리와 패치 아이템 유무가 서로 다른 호스트, 마지막 수집값이 빈 호스트를 각 1대 선정한다. 월 중간 날짜를 입력해 목록·상세·CSV를 비교한다.
2. 기술명과 표시명이 다른 호스트, 사용률 키가 두 개 있는 호스트에서 동일 기간의 평균·Peak와 CSV의 HOST·ITEM·행 수를 비교한다. CPU/Memory 복사 표의 ITEM 값이 실제로 무엇이었는지는 원본 파일 한 개로 확인할 수 있다.
3. 설정이 없는 계정으로 Peak의 최초·초기화 결과를 보고, 기존 프로파일이 있는 계정으로 저장된 조회 범위와 임계값이 이어지는지 확인한다.
4. 고객 운영 DB의 세션·감사 보관 기간을 확인하고 생성한 지 60일이 안 된 미접속 계정과 오래된 계정을 한 건씩 대조한다.

OTP·MPASS 로그인은 별도 미구현 기능이다. 윈도우 전체·ESXi는 이관 필요성이 미확정이고 Box 사용현황은 기존 결정으로 제외했다. 이 항목들은 구현된 23개 액션의 검증 결과와 구분한다. [남은 작업과 결정 사항](./미구현_목록.md)
