# 저사용 / 고사용 서버: 시간 계산 개선안

**지금은 5버전과 똑같이 계산한다. 아래 개선안은 아직 적용하지 않았다.** (2026-11-24 결정: 5버전대로 둔다)
고객과 이야기할 때 쓰려고 쉽게 정리했다.

## 지금 어떻게 계산하나 (5버전과 같음)

화면에서 시간 구분을 고르면 그 시간의 값만 모아 평균과 Peak 를 낸다.

| 시간 구분 | 들어가는 시간 |
|---|---|
| 업무시간 | **평일(월~금)** 09:00 ~ 18:00 |
| 업무외시간 | **매일** 18:00 ~ 다음 날 09:00 |
| 전체 | 하루 24시간, 매일 |

그림으로 보면 이렇다. (■ 업무시간, □ 업무외시간, · 어디에도 안 들어감)

```
          00시      09시           18시      24시
월~금     □□□□□□□□□ ■■■■■■■■■ □□□□□□
토, 일    □□□□□□□□□ ········· □□□□□□
```

## 개선안 1. 주말 낮 시간이 빠진다 (가장 먼저 볼 것)

- **문제**: 위 그림의 `·` 부분, 즉 토·일요일 09~18시 값이 "업무시간"에도 "업무외시간"에도 들어가지 않는다.
  주말 낮에 CPU 가 높았던 서버라도 업무외시간 결과에는 드러나지 않는다.
- **바꾸는 방법**: 업무외시간을 "업무시간이 아닌 모든 시간"으로 정한다. 그러면 주말 낮도 업무외시간에 들어간다.
- **결과 변화**: 업무외시간의 평균과 Peak 가 5버전과 달라진다. 업무시간과 전체는 그대로다.
- **손댈 곳**: `includes/ServerUsageService.php` 의 업무외시간 조건 한 곳.

## 개선안 2. 업무시간 Peak 에 밤 시간 값이 섞인다

- **문제**: 5버전은 업무시간 **평균**은 09~18시 값으로 내지만, 업무시간 **Peak** 는 그날 **하루 전체**의 최대값을 쓴다.
  그래서 새벽 백업이나 배치 때문에 오른 값이 "업무시간 Peak"로 나온다.
  예) 낮에는 내내 20% 인데 새벽 3시 백업 때 95% 였던 서버 → 업무시간 Peak 95%
- **바꾸는 방법**: 설정 한 줄. `conf/serverusage.conf.php` 의 `business_peak_whole_day` 를 `false` 로 바꾸면 업무시간 안의 최대값만 본다.
- **결과 변화**: 업무시간 Peak 가 5버전보다 낮게 나오는 서버가 생긴다. 그래서 고사용 서버 목록(Peak 70% 이상)에서 빠지는 서버가 생길 수 있다.

## 개선안 3. 공휴일이 업무일로 계산된다

- **문제**: 설날, 추석 같은 평일 공휴일도 업무시간에 들어간다. 사용량이 낮은 날이 섞여 업무시간 평균이 내려간다.
- **바꾸는 방법**: 설정 파일에 공휴일 날짜 목록을 넣고, 그날은 업무시간에서 뺀다. (새로 만들어야 하는 기능)
- **결과 변화**: 공휴일이 있는 기간을 조회하면 업무시간 평균이 5버전보다 조금 올라간다.
- **주의**: 공휴일 목록은 매년 누군가 채워 넣어야 한다.

## 정리

| 개선안 | 일의 양 | 5버전과 숫자가 달라지나 | 추천 |
|---|---|---|---|
| 1. 주말 낮을 업무외시간에 넣기 | 작음 (조건 한 곳) | 업무외시간만 달라짐 | 가장 먼저 |
| 2. 업무시간 Peak 를 업무시간 안에서만 | 아주 작음 (설정 한 줄) | 업무시간 Peak 가 달라짐 | 고객 확인 뒤 |
| 3. 공휴일 빼기 | 중간 (새 기능 + 매년 관리) | 공휴일 낀 기간만 조금 | 요청이 있을 때 |

셋 다 5버전과 숫자가 달라지므로 고객이 "5버전과 같은 숫자"를 원하면 지금대로 둔다.
