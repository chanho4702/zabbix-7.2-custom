# 5버전 → 7버전 화면별 비교

## 1. 머리말

### 1.1 이 문서는 무엇인가

화면마다 "5버전은 이렇게 했다 → 7버전은 이렇게 바뀌었다, 이유" 를 한곳에 모았다.
7버전 모듈 코드를 git 에서 보고 손으로 따라 치는 개발자가 읽는다. 바뀐 곳마다 이유를 알고 칠 수 있게 하려는 것이다.

- 작성일: 2026-11-24
- 기준: 고객 Zabbix 7.0.26, 브랜치 `main`
- 함께 볼 문서
  - 5버전 동작 자체: [5버전_구현_방식.md](5버전_구현_방식.md)
  - 7버전 화면 설명: [../02_화면별/README.md](../02_화면별/README.md)
  - 7버전 데이터 출처: [../02_화면별/데이터_출처_요약.md](../02_화면별/데이터_출처_요약.md)
  - 받아야 할 5버전 파일: [../04_남은_작업/미구현_목록.md](../04_남은_작업/미구현_목록.md)

### 1.2 읽는 법

- 2장 표로 전체를 본다. 그다음 3장에서 고칠 화면 절만 읽는다. 4장은 모든 화면에 걸친 변화다.
- 화면 절은 모두 같은 다섯 칸이다: a. 5버전 구현 / b. 7버전 구현 / c. 바뀐 점 표 / d. 따라 칠 때 순서 / e. 5버전 파일이 없어 확인 못 한 것.
- 근거는 `파일:줄` 로 적는다.
  - 5버전 파일은 모두 `v5_restored/src/` 아래에 있다. 이 문서에서는 앞부분을 줄여 파일 이름만 적는다. 예) `CControllerLowserver.php:102`.
  - 7버전 파일은 `ui/modules/dmove/` 아래에 있다. 이 문서에서는 그 아래 경로만 적는다. 예) `actions/reports/lowserver/LowServerList.php:96`.
  - 5버전 화면 기록은 `v5_restored/screens_*.md` 이다.
- 5버전 커스텀 클래스 이름에는 회사 이름 접두어가 붙어 있다. [5버전_구현_방식.md](5버전_구현_방식.md) 1.4 처럼 접두어를 `...` 으로 바꿔 적는다. 예) `...Daily.php:967` = `v5_restored/src/C<접두어>Daily.php` 의 967번째 줄. 기본 트레잇(접두어만으로 된 이름)은 `C....php` 로 적는다.
- 5버전 줄 번호는 **복원본 기준**이다. 앞부분이 빠진 파일은 원본 줄 번호와 다르다. `⟦?⟧` 는 읽지 못한 글자다.
- 커밋은 `해시 "제목"` 으로 적는다. `git -C C:\zabbix show <해시>` 로 그 커밋이 바꾼 내용을 본다.

### 1.3 "숫자가 5버전과 같은가" 칸의 뜻

| 표시 | 뜻 |
|---|---|
| 같음 | 같은 DB 라면 화면에 나오는 숫자와 줄이 5버전과 같다 |
| 다름 | 같은 DB 라도 숫자나 줄이 달라질 수 있다. 어떤 경우에 다른지 같이 적는다 |
| 설정으로 선택 | `conf/*.conf.php` 값이나 사용자가 고른 값에 따라 같게도, 다르게도 된다 |
| 확인 불가 | 5버전 소스가 없어 비교할 수 없다 |
| 표시만 | 값은 같고 글자 모양(색, `-`, 소수 자리 등)만 다르다 |

### 1.4 "이유" 칸의 네 가지

| 이유 | 뜻 |
|---|---|
| 7.0 구조 변경 | Zabbix 7.0 에서 표, API, 화면 틀이 바뀌어 그대로 옮길 수 없었다 |
| 5버전 결함 수정 | 5버전 코드가 틀렸거나 위험해서 고쳤다 |
| 사용자 결정 | 작업 중 사용자가 정했다 (날짜가 있으면 같이 적는다) |
| 5버전 파일 없음 → 추정 | 5버전 소스를 받지 못해 화면 기록이나 비슷한 코드로 추정했다 |

## 3. 화면별 비교

### 3.1 SW 인벤토리 (+Agent 상태 창)

#### a. 5버전 구현

**파일**

| 종류 | 파일 | 상태 |
|---|---|---|
| 라우팅 | `routing.php:12-14` (`swinventories`, `swinventories.view.csv`), `routing.php:24` (`popup.agent`) | 전체 |
| 컨트롤러 | `CControllerSwinventories.php` | 원본 1~3줄, 55줄, 287줄 이후 없음 |
| 트레잇 | `C....php`, `...Inventoris.php`, `...Filter.php`, `...Itms.php` (`CControllerSwinventories.php:8-13`) | 전체 |
| 클래스 | `...HostAgent.php`, `...Middle.php`, `...Key.php:28-121` | 전체 (`...HostAgent.php:78`, `:142` 오른쪽 잘림) |
| 규칙 파일 | `swinventory.json` (가운데 처리 순서 `:8-21`, 열 `:27-56`, 열 함수 `:57-88`) | 전체 |
| 없음 | 뷰 `inventory/swinventories`, `CControllerSWInventCSV`, `CControllerPopupAgent` + 뷰, `...Data` | - |

**데이터 조회**

1. 필터는 프로파일 `web.swinventory.filter.*` 에 저장한다 (`CControllerSwinventories.php:83-135`). 항목은 groupids, hostids, os, web, was, db, duplex, itms, Agent 체크 3개다.
2. Zabbix 호스트: `API::Host()->get(output hostid,name,host; groupids; hostids; preservekeys)` (`CControllerSwinventories.php:200-208`). API 를 거치므로 **로그인한 사용자 권한으로 걸러진다**. `checkPermissions()` 는 그냥 `true` 다 (`:66-69`).
3. ITSM 목록: `SELECT id, ci_name, ip_address, description FROM eaonl.itsm_info` (`...Itms.php:29-42`). 표가 없으면 빈 배열이다. 그러면 화면 줄이 0개다.
4. 연결: `strtolower(host) == strtolower(ci_name)` 이면 줄 키가 hostid, 아니면 `"itsm_".id` (`CControllerSwinventories.php:214-232`). 연결된 줄은 Agent "설치" 표시용 배열에 1을 넣는다 (`:220`).
5. SW 값
   - `DBExtend` (`...Inventoris.php:366-454`) 는 `items` 에서 itemid 만 찾는다 (`:372`). 이력 조회는 주석이다 (`:389-403`). 그래서 이 단계의 값은 늘 빨간 `--` 나 `-` 다 (`:426-448`).
   - 마지막 `middle_inventory` (`...Inventoris.php:155-205`) 가 `host_inventory` 의 `os`, `software_app_a~d` 중 **비어 있지 않은 값만** 덮어쓴다. 실제 값은 여기서 나온다.
6. Agent 판정 (`...HostAgent.php`)
   - 연결된 줄 → "설치" (`:47-65`)
   - 그 밖에는 `extends_agent` 의 최신 줄을 본다 (`:78`). agent=2 → 미설치, 4 → 예외, 그 밖의 값 → 설치, 줄 없음 → 미설치, 조회 실패 → "조회오류" (`:80-101`)
   - 설치가 아니면 상태 글자에 `PopUp("popup.agent",{hostid})` 링크를 단다 (`:105-123`). 최근 5줄 읽기 `:125-136`, INSERT `:138-145`.
   - 표가 없으면 화면을 열다가 `CREATE TABLE` 을 실행한다 (`:71-74`, `:163-175`).

**판정 규칙**

- 글자 필터: 소문자로 바꿔 `strpos` 부분 일치. 필드가 없거나 빨간 `-` 인 줄은 지운다 (`...Filter.php:19-60`).
- Agent 체크 기본값: `filter_set` 도 `page` 도 없는 요청이면 3개를 매번 "1" 로 되돌린다 (`CControllerSwinventories.php:139-152`).
- Agent 마스크: 설치 1 + 미설치 2 + 예외 4 (`:279-284`). 마스크를 적용하는 코드는 빠진 구간(287줄 이후)에 있다.
- 정렬 허용 값: `name, osname, _osname, _web, _was, _db, agent, _agent, db, duplex` (`:58-60`). 기본 정렬은 모른다.

**알려진 5버전 결함**

- `$host_name` 을 반복마다 비우지 않는다. 연결 안 된 줄에 앞 줄 표시명이 찍힌다 (`CControllerSwinventories.php:219`, `:226`).
- ci_name 이 같은 ITSM 줄 둘이 같은 hostid 키에 덮어써져 한 줄만 남는다 (`:224`).
- hostid 를 SQL 문자열에 그대로 붙인다 (`...HostAgent.php:78`).
- `swinventory.sql` 의 DB 뷰는 어떤 PHP 도 읽지 않는다 (`v5_restored/INDEX.md` 1장 표).

#### b. 7버전 구현

**파일**

| 종류 | 파일 |
|---|---|
| 등록 | `manifest.json:10-27` (액션 4개), `Module.php:81` (메뉴) |
| 컨트롤러 | `actions/inventory/swinventory/SwInventoryList.php` (CSRF 끔 `:101-108`, 입력 `:129-158`, 권한 `:172-176`, 실행 `:202-282`, 열 `:293-306`, Agent 체크 기본값 `:318-330`) |
| 상태 창 | `actions/inventory/swinventory/AgentEdit.php`, `AgentSave.php`, `views/inventory/swinventory.agent.php:26-99`, `views/js/inventory/swinventory.list.js.php:45-101` |
| 서비스 | `includes/SwInventoryService.php`, `includes/AgentStatusRepository.php`, `includes/SoftwareResolver.php`, `includes/ItsmRepository.php`, `includes/HostHelper.php` |
| 설정 | `conf/swinventory.conf.php:35,38`, `conf/itsm.conf.php` (스키마/표 이름) |
| SQL | `sql/extends_agent.sql:10-20` (5버전 표 정의 + 색인 1개) |
| 뷰 | `views/inventory/swinventory.list.php` (필터 `:74-125`, 표 `:145-207`, 경고 `:218-235`) |

**데이터 조회**

1. Zabbix 호스트: 직접 SQL `hosts h LEFT JOIN host_inventory hi`, `status IN (0,1)`, `flags IN (0,4)` (`SwInventoryService.php:306-315`). **권한과 관계없이 전체 호스트**다. 사용자가 볼 수 있는 호스트(`:182-185`)는 인벤토리 상세 링크를 달지 정하는 데만 쓴다 (`:258-259`).
2. ITSM: `ItsmRepository.php:62-86` 에서 열 4개를 읽는다. 표가 없으면 null 이다 (`:181-191`). 그때는 Zabbix 호스트 목록으로 대신하고 경고를 띄운다 (`SwInventoryService.php:202-215`).
3. SW 값: `SoftwareResolver.php:80-106` 이 ITSM 값 → 인벤토리 값 → 빈 문자열 순서로 고른다. 대응표는 `:45-51` (`os`, `software_app_a~d`).
4. IP 는 ITSM 값, 비면 `HostHelper::mainIp` (`SwInventoryService.php:240-244`). Description 은 ITSM 값, 비면 호스트 설명 (`:247-251`).
5. Agent 판정: 5버전과 같은 규칙 (`SwInventoryService.php:387-410`). 최신 기록은 `MAX(clock)` JOIN 으로 한 번에 읽는다 (`AgentStatusRepository.php:61-91`).
6. 상태 저장 (`AgentSave.php`)
   - CSRF 검사를 켠다 (`:36-38`).
   - 키는 `itsm_` 로 시작하고 20자 이하 (`:44-46`), agent 값은 2 또는 4 (`:57-58`), 사유 2048자 (`:69-72`).
   - 표가 없으면 오류 응답 (`:95-100`). 표를 자동으로 만들지 않는다.
   - 사용자 열: `username` ← `users.name`, `useralias` ← `users.username` (`AgentStatusRepository.php:140-164`).

**판정 규칙**

- 글자 필터: `mb_stripos` 부분 일치 (`SwInventoryService.php:436-473`).
- Agent 체크: 비트 OR 마스크. 하나도 체크하지 않으면 거르지 않는다.
- 기본값: 프로파일에 저장된 값이 없을 때만 3개 모두 1 (`SwInventoryList.php:318-330`).
- 정렬: 10개 열 모두, 기본 `host` 오름차순 (`SwInventoryService.php:484-494`).

- 성능 데이터 추세 분석 전체: `data.analysis.js` 등 필요. 받으면 다시 만든다.
- 로그인 인증 함수 본문.
