# 성능 데이터 추세 분석 (`perftrend.list`)

## 1. 한눈에

| 항목 | 내용 |
|---|---|
| 메뉴 위치 | 보고서 > 성능 데이터 추세 분석 (`Module.php` 의 `REPORT_MENUS`) |
| 주소 | `zabbix.php?action=perftrend.list` |
| 상태 | **빈 페이지.** 제목, "이 화면은 아직 구현되지 않았습니다." 안내 상자, 열 없는 빈 표만 있다 |
| 5버전 액션 | `data.analysis` (화면 제목 "데이터 추세 분석") |
| 내보내기 | 없음 (5버전은 [CSV 내보내기] 버튼이 있었다) |
| 권한 | 사용자 유형 Zabbix User 이상 (`checkPermissions()`, TODO 로 바꿀 자리 표시됨) |

## 2. 이 화면은 무엇을 하나

5버전에서는 여러 서버의 성능 값(CPU, 메모리 등)을 **한 그래프에 겹쳐 그려** 기간에 따른 추세를 비교하고, 그 값을 CSV 로 받는 화면이었다.
호스트 패턴과 아이템 패턴을 여러 줄(데이터 셋) 추가하고 줄마다 색과 그래프 모양을 정하는 방식이라, 운영 담당자가 "이 서버들 CPU 가 지난주와 비교해 어땠나" 같은 것을 그때그때 그려 볼 때 썼을 것으로 보인다(실제 사용 목적은 확인 필요).
7버전에서는 아직 만들지 않았다. **같은 기능이 Zabbix 7 대시보드의 "그래프" 위젯에 그대로 있기 때문에** 독립 화면을 만들지, 위젯으로 대체할지를 먼저 정해야 한다. 이 문서의 4장과 8장이 그 비교다.

### 5버전 화면 (참고)

| 영역 | 내용 |
|---|---|
| 위쪽 | 그래프. 가로축은 시간(`MM-DD HH:MM` 눈금) |
| 아래쪽 탭 [데이터 셋] | 데이터 셋 여러 줄. 줄마다 색상 + 호스트 패턴 [선택] + 아이템 패턴 [선택] + 삭제(×), [+ 새로운 데이터 셋을 추가] |
| 데이터 셋 상세 옵션 | 기본 색상, 그래프 형식(선 / 포인트 / 막대 그래프 / Bar), 너비, 포인트 사이즈, 투명도, 채우기, 결손 데이터(없음 / 접속됨 / 0 으로 처리), Y축(왼쪽 / 오른쪽), 타임 시프트, Aggregation function, Aggregation interval, Aggregate(각 아이템 / 데이터 셋) |
| 아래쪽 탭 [기간] | 그래프에 표시할 기간 (내용 확인 못 함) |
| 제목 오른쪽 | [CSV 내보내기] |
| 표 | 없음 |

이 구성은 Zabbix 5.0 대시보드 "그래프" 위젯(코어 `svggraph`)의 설정 폼과 같다. 5버전 소스에서 확인한 결과(2026-11-23), 코어의 대시보드/위젯 컨트롤러를 복사해 독립 화면으로 만들고 CSV 내보내기를 붙인 것이 맞다 (5장).

```
데이터 추세 분석                                         [CSV 내보내기]
┌ 그래프 ────────────────────────────────────────────────────────────┐
│  ~~~~~/\~~~~~~~~ (데이터 셋 1)                                       │
│  ------\__/----- (데이터 셋 2)                                       │
│  11-20 13:31   11-20 13:46   11-20 14:02   11-20 14:17               │
└──────────────────────────────────────────────────────────────────────┘
 [데이터 셋] [기간]
  ■ [호스트 패턴      ][선택]  [아이템 패턴      ][선택]  ×
  ■ [호스트 패턴      ][선택]  [아이템 패턴      ][선택]  ×
  [+ 새로운 데이터 셋을 추가]
```

## 4. 어떻게 만들었나 (동작 순서)

### 4.1 지금 코드가 하는 일

1. `zabbix.php?action=perftrend.list` → `manifest.json` → `Modules\DMove\Actions\Reports\PerfTrend\PerfTrendList`, 뷰 `reports/perftrend.list`.
2. `PerfTrendList::init()` — `disableCsrfValidation()`.
3. `PerfTrendList::checkInput()` — `'page' => 'ge 1'` 하나만 받는다(템플릿에서 온 자리).
4. `PerfTrendList::checkPermissions()` — `getUserType() >= USER_TYPE_ZABBIX_USER && !CWebUser::isGuest()` (게스트 계정 제외).
5. `PerfTrendList::doAction()` — `$rows = []` 로 두고 `title`(번역된 "성능 데이터 추세 분석")과 함께 뷰로 넘긴다. 데이터 조회는 없다.
6. 뷰 `views/reports/perftrend.list.php` — `CHtmlPage` 에 제목, 노란 안내 상자(`makeMessageBox(ZBX_STYLE_MSG_WARNING, ...)`), 열 없는 `CTableInfo` 를 붙인다.

API 호출, SQL, 계산이 없다.

### 4.2 방향 비교: 대시보드 위젯 대체(가) vs 독립 화면(나)

#### (가) 코어 대시보드 "그래프" 위젯으로 대체 — 권장

방법:

1. 대시보드를 하나 만든다(예: "성능 데이터 추세 분석"). 공유 대상 사용자 그룹을 정한다.
2. "그래프" 위젯을 올리고 데이터 셋에 호스트 패턴 / 아이템 패턴을 넣는다. 색, 선/포인트/막대, 집계 함수와 간격, Y축, 타임 시프트, 결손 데이터 처리가 5버전 화면과 같은 항목으로 있다.
3. 기간은 대시보드 위쪽 시간 선택기로 바꾼다.
4. 값이 필요하면: 모니터링 > 최신 데이터 > 아이템의 [그래프] → 보기를 "Values"(값)로 바꾸고 "As plain text" 버튼(한국어 화면에서는 번역된 이름)을 누르면 값 목록을 글자로 받을 수 있다(코어 `history.php` 의 plaintext). 여러 아이템을 한 번에 받는 CSV 는 코어에 없다.
5. 메뉴 "성능 데이터 추세 분석" 은 지우거나, 그 대시보드 주소(`zabbix.php?action=dashboard.view&dashboardid=번호`)로 가는 메뉴로 바꾼다. 모듈 메뉴에 URL 을 거는 것은 `Module.php` 에서 `CMenuItem` 에 `setUrl()` 을 쓰면 된다.

#### (나) 5버전처럼 독립 화면으로 구현

두 가지 크기가 있다.

| | (나-1) 5버전과 같은 화면 | (나-2) 간단한 독립 화면 |
|---|---|---|
| 내용 | 그래프 위젯의 설정 폼(데이터 셋 편집기)과 그리기 코드를 모듈 화면에 넣고 CSV 를 붙인다 | 필터(호스트 그룹/호스트, 아이템 키 또는 패턴, 기간, 집계 간격) + 그래프 + 값 표 + CSV/Excel |
| 그래프 | 코어 `widgets/svggraph` 의 폼, JS, `CSvgGraph` 를 가져다 써야 한다 | 코어 `chart.php?itemids[]=...&from=...&to=...` 이미지(최신 데이터의 그래프와 같은 것)를 `<img>` 로 붙이거나, 그래프는 생략 |
| 데이터 | 위젯과 같은 방식 | `trend.get` / `history.get` API, 또는 저사용/고사용 화면처럼 `trends` 집계 SQL (`ServerUsageService` 방식 재사용) |
| 개발량 | 많다. 위젯 폼의 JS 와 검증 규칙이 크다 | 보통. 기존 화면(`ServerUsageController`, `HostFilter`, `ExportTrait`)을 본떠 만들 수 있다 |
| 버전 업그레이드 | 코어 위젯 내부 코드에 기대므로 Zabbix 버전이 바뀔 때마다 깨질 수 있다 | 공개 API 와 `chart.php` 만 쓰면 비교적 안전 |
| 5버전과의 차이 | 거의 같다 | 데이터 셋 여러 줄, 색/형식 옵션이 없다 |
| 필요한 5버전 정보 | `data.analysis` 컨트롤러, CSV 열 구성, 집계 방식 | 같음 + 사용자가 실제로 쓰던 패턴(어떤 아이템을 주로 봤는지) |

#### 비교 요약

| 기준 | (가) 위젯 대체 | (나-1) 같은 독립 화면 | (나-2) 간단한 독립 화면 |
|---|---|---|---|
| 개발 / 유지보수 | 코드 없음 | 많음 / 업그레이드 때마다 점검 | 보통 / 적음 |
| 그래프 기능 | 5버전과 같은 항목, 코어가 계속 개선 | 같음 | 줄어듦 |
| 설정 저장 | 대시보드에 저장, 공유 가능 | 5버전은 저장 방식 확인 필요 | 사용자 프로파일에 필터 저장 |
| CSV | 여러 아이템 한 번에는 없음 (아이템별 텍스트 보기만) | 가능 | 가능 (Excel 포함) |

| 결정에 필요한 것 | CSV 가 꼭 필요한지 | `data.analysis` 소스 | CSV 열 구성, 자주 보는 아이템 |

**권장:** (가). CSV 가 업무에 꼭 필요하다고 확인되면 (나-2) 를 "CSV 내보내기 전용 화면"으로 작게 만들고 그래프는 위젯에 맡긴다. 이 경우 "CPU/Memory 전체 사용률 추출"(`usageexport.list`) 화면과 역할이 겹치는지도 함께 본다.

## 8. 개선점

### 이미 반영한 개선

- 메뉴와 빈 화면, 안내 상자만 두어 "만들어지지 않은 화면" 임을 사용자가 알 수 있게 했다(빈 화면을 오류로 오해하지 않게).
- 방향 비교와 할 일을 컨트롤러 머리말과 이 문서에 정리했다.

### 남은 개선 제안

| 제안 | 효과 | 5버전과 결과가 달라지나 (합의 필요?) |
|---|---|---|
| (가) 대시보드 그래프 위젯으로 대체하고 메뉴를 대시보드 링크로 | 코드 0줄, 업그레이드 부담 없음, 그래프 설정을 저장/공유 | 화면 위치와 모양이 바뀌고 CSV 가 없어진다 → 합의 필요 |
| CSV 가 필요하면 (나-2) 를 내보내기 전용으로 작게 | 필요한 값만 받는다 | CSV 열 구성을 5버전과 맞춰야 같다 → 5버전 소스 확인 필요 |
| 자주 쓰는 비교(예: 서버 그룹별 CPU)를 미리 만든 대시보드 템플릿으로 제공 | 매번 데이터 셋을 다시 만들 필요가 없다 | 기능 추가라 영향 없음 |
| 결정 전까지는 메뉴를 숨김 | 빈 화면 노출을 피한다 | 메뉴가 잠시 없어진다 → 합의 필요 |

## 9. 확인 방법

### 테스트 환경 (http://127.0.0.1:18970, Admin / zabbix, `dev/compose.yaml`)

지금 화면:

1. 보고서 > 성능 데이터 추세 분석 → 제목, 노란 "이 화면은 아직 구현되지 않았습니다.", 빈 표가 보이면 정상. 브라우저 탭 제목도 "성능 데이터 추세 분석".
2. 사용자 언어를 영어로 → "Performance trend analysis", "This page is under construction.".

(가) 대체안 미리 보기:

1. 대시보드 > [대시보드 만들기] → 위젯 추가 → 형식 "그래프".
2. 데이터 셋: 호스트 패턴 `Zabbix server`, 아이템 패턴 `*` 대신 서버 내부 아이템 몇 개(예: 이름에 "Utilization" 이 들어간 것). 테스트 환경에는 에이전트가 없어 OS 아이템 값은 비어 있을 수 있다.
3. 데이터 셋을 하나 더 추가해 색과 형식(선/막대)을 바꾸고, 집계 함수(avg, 1h)를 넣어 본다. 5버전 화면 3장의 항목이 모두 있는지 대조한다.
4. 모니터링 > 최신 데이터에서 한 아이템의 그래프를 열고, 보기를 "Values"(값)로 바꾼 뒤 "As plain text" 버튼으로 값 목록이 나오는지 본다(CSV 대체 가능성 확인).

### 고객환경에서

1. 5버전 `zabbix.php?action=data.analysis` 를 열어 실제로 저장된 데이터 셋이 있는지, [CSV 내보내기] 결과 파일의 열 구성을 본다.
2. 담당자에게 이 화면을 얼마나, 무엇을 보려고 쓰는지 묻는다. CSV 를 실제로 쓰는지가 (가) / (나) 결정의 핵심이다.
3. (가) 로 정하면 같은 데이터 셋으로 7버전 대시보드를 만들어 5버전 그래프와 모양을 비교한다.
