# 화면별 데이터 출처 요약

## 머리말

- 목적: dmove 모듈의 화면마다 **어떤 데이터를, 어디서, 어떻게 읽는지** 한 곳에 모았다. 데이터가 이상할 때 어디를 볼지 찾는 용도다.
- 근거: `ui/modules/dmove` 의 코드만 보고 적었다. 위치는 `파일:줄` 로 적는다. 경로는 모듈 폴더(`ui/modules/dmove/`) 기준이다. 코어 파일은 `ui/` 부터 적는다.
- 기준 날짜: 2026-11-24. 코어는 Zabbix 7.0 기준이다.
- 읽는 법
  - 화면마다 같은 5개 절이다. 1 한 줄 요약, 2 호출하는 데이터(표), 3 판정·계산 기준, 4 Zabbix 기본 기능 기준인지, 5 5버전과 다른 데이터 출처.
  - "권한 적용 여부" 열: **API** 면 로그인한 사용자의 호스트/사용자 권한이 코어에서 걸린다. **직접 SQL** 이면 권한이 걸리지 않으므로, 어떻게 거르는지 따로 적었다.
  - "프로파일" 은 코어 `CProfile` 이다. DB `profiles` 표에 사용자별로 저장된다.
  - 공통 부품(HostFilter, ItsmRepository 등)이 읽는 데이터는 맨 끝 "공통 부품" 절에 한 번만 자세히 적었다. 화면 표에는 이름만 적는다.
- 화면별 상세 설명은 같은 폴더의 화면 문서를 본다. 5버전 쪽 근거는 `../03_5버전_분석/5버전_구현_방식.md` 다.

### 1.3 판정·계산 기준

- 행의 기준은 ITSM 표다. ITSM 행 1개 = 화면 줄 1개. `ci_name` 이 빈 행은 건너뛴다 (`SwInventoryService.php:225-227`).
- 매칭: ITSM `ci_name` 과 Zabbix `hosts.host` 를 `mb_strtolower` 로 바꿔 **완전 일치** 비교한다 (`:196`, `:229-233`). 표시명(`name`)이 아니라 기술 이름(`host`)이다.
- IP, Description: ITSM 값이 먼저, 비어 있으면 Zabbix 값 (`:240-251`).
- Agent 상태 (`:375-420`)

  | 조건 | 상태 |
  |---|---|
  | Zabbix 호스트와 매칭됨 | 설치(1) |
  | 매칭 안 됨, `extends_agent` 최신 줄의 `agent` = 2 | 미설치(2) |
  | 매칭 안 됨, 최신 줄 `agent` = 4 | 예외(4) |
  | 매칭 안 됨, 최신 줄 `agent` 가 그 밖의 값 | 설치(1) |
  | 매칭 안 됨, 기록 없음 (또는 표 없음) | 미설치(2) |
  | ITSM 미연동(대체 모드) | 모두 매칭되므로 설치. 입력 불가 |

- 최신 줄 = 같은 `hostid` 중 `clock` 최대. 같은 초에 두 줄이면 아무 줄이나 하나 (`AgentStatusRepository.php:58-59`).
- 글자 필터: 대소문자 무시 부분 일치(`mb_stripos`), 여러 개면 AND (`SwInventoryService.php:436-454`).
- Agent 필터: 체크한 값의 비트 OR 와 행 상태의 비트 AND 가 0 이 아니면 남긴다. 하나도 체크 안 하면 전체 (`:457-469`).
- 정렬: `CArrayHelper::sort` (대소문자 무시, 자연 정렬). 모르는 열이면 `host` (`:484-494`).
- 화면 목록은 `CPagerHelper::paginate` 로 자른다. 내보내기는 자르지 않은 전체 (`SwInventoryList.php:246`, `:272`).

### 1.4 Zabbix 기본 기능 기준인지

- 기본 그대로: 호스트 인벤토리 필드(`os`, `software_app_a~d`), 인터페이스의 기본(main)/종류(type), 인벤토리 상세 화면 링크.
- 커스텀: 행의 기준인 ITSM 표, Agent 상태 표 `extends_agent`, "인벤토리 필드 A~D = WEB/WAS/DB/이중화" 라는 뜻 매기기.
- 주의: Zabbix 호스트를 API 가 아니라 직접 SQL 로 읽어 사용자 호스트 권한이 걸리지 않는다.

### 1.5 5버전과 다른 데이터 출처

- 5버전은 Zabbix 호스트를 `API::Host()->get()` (그룹 필터 적용)으로 읽었다. 7버전은 `hosts` 표를 직접 전체 읽는다.
- 5버전은 `zabbix.items` 에서 OS/WEB 등 아이템 키를 찾았지만 값을 읽는 쿼리가 주석이었다. 7버전은 아이템을 읽지 않고 `host_inventory` 만 읽는다.
- `extends_agent` 를 5버전은 서버마다 한 번씩 조회했다. 7버전은 한 번에 읽고, 표가 없을 때 만들지 않는다.

액션: `uptime.list`

### 2.1 한 줄 요약

호스트마다 `system.uptime` 의 마지막 값으로 가동 시간과 부팅 시각을 보여 준다.

### 2.3 판정·계산 기준

- 행: `system.uptime` 활성 아이템이 있는 호스트만. 아이템 1개 = 행 1개 (`:258`).
- 값 있음: `lastclock != 0` (`:260`). `lastvalue` 는 코어 `item.get` 이 이력에서 읽은 값이다. 코어는 설정 "History period"(`CSettingsHelper::HISTORY_PERIOD`) 안의 값만 준다 (`ui/include/classes/api/services/CItem.php:1781-1782`). 그 기간보다 오래 끊긴 호스트는 `-`.
- 가동 일수 = `intdiv(가동 초, 86400)`. 필터 "N day 이상" 은 `가동 일수 >= N` 이면 남긴다. 필터를 걸었는데 값이 없으면 뺀다 (`:269-271`).
- 서버 Time = `N 일, HH:MM:SS` (`gmdate` 로 나머지 초) (`:299-301`).
- 서버 start = `lastclock - 가동 초` 를 `Y/m/d H:i:s` 로 (`:284`).
- OS: 인벤토리 `os`. 인벤토리가 꺼진 호스트는 빈 칸 (`:280`). OS 필터는 코어 `searchInventory` (부분 일치).
- Description: ITSM 설명(호스트 표시명 소문자로 찾음) -> 없으면 Zabbix 호스트 설명 (`:278`).
- 정렬: `uptime` 은 숫자 비교, 값 없는 줄은 항상 맨 뒤. 같으면 이름 순 (`:312-335`).

### 2.4 Zabbix 기본 기능 기준인지

- 기본 그대로: 아이템 키 `system.uptime`, 아이템의 마지막 값(`lastvalue`, `lastclock`), 인벤토리 `os`, 호스트 그룹/호스트 권한.
- 커스텀: Description 의 ITSM 우선 규칙.

### 2.5 5버전과 다른 데이터 출처

- 5버전은 마지막 값을 `Manager::History()->getLastValues()` 로 직접 읽고, 일수 필터용 SQL 을 아이템마다 실행했다. 7버전은 `item.get` 의 `lastvalue` 를 쓰고 일수는 PHP 로 계산한다.
- 5버전은 호스트·아이템을 "검색 결과 제한 + 1" 개까지만 읽었다. 7버전은 제한하지 않는다.
- Description 을 5버전이 어디서 읽었는지는 뷰가 없어 확인 못 함. 7버전은 ITSM 우선.

## 3. 저사용 / 고사용 서버 사용현황

액션: `lowserver.list`, `lowserver.export`, `highserver.list`, `highserver.export`, `serverusage.threshold`, `serverusage.threshold.save`

두 화면은 같은 부모 컨트롤러(`ServerUsageController`)를 쓴다. 다른 것은 판정 식과 프로파일 접두어(`web.dmove.lowserver.` / `web.dmove.highserver.`)뿐이다.

### 3.1 한 줄 요약

### 3.3 판정·계산 기준

- 기간: 시작일 00:00:00 ~ 종료일 23:59:59 (`ServerUsageController.php:263-264`). 시작 > 종료, 형식 오류, `max_period_days`(366일) 초과면 조회하지 않는다 (`:267-278`).
- 시간 계산은 사용자 시간대 기준이다. `date('Z', 시작)` 차이를 `clock` 에 더해 날짜 번호와 그날의 초를 SQL 에서 구한다 (`ServerUsageService.php:203-211`).
- 시간대 (`:230-239`)

  | 값 | 평균에 넣는 시간별 값 | 요일 |
  |---|---|---|
  | `all` | 전부 | 전부 |
  | `work` | 그날 초 `>= 9시` 그리고 `< 18시` (`business_hours`) | `business_days` (월~금) 만 |
  | `night` | 그날 초 `< 9시` 또는 `>= 18시` | 전부 |

- Peak: `work` 이고 `business_peak_whole_day = true`(기본) 면 그 업무일 **하루 전체**의 `MAX(value_max)`. 그 밖은 고른 시간대 안의 최대 (`:246`, `:258`).

- 한 호스트에 아이템이 여럿이면 기간 평균이 큰 아이템의 값을 쓴다 (`:301-306`).
- 값이 없는 호스트(아이템 없음, 기간 안 trends 없음)는 목록에 나오지 않는다 (`ServerUsageController.php:448-449`).
- 저사용: `평균 <= low_avg` 그리고 `Peak <= low_peak` (기본 30 / 70) (`actions/reports/lowserver/LowServerList.php:95`).
- 고사용: `평균 >= high_avg` 그리고 `Peak >= high_peak` (기본 50 / 70) (`actions/reports/highserver/HighServerList.php:98`).
- 평균과 Peak 는 소수 둘째 자리로 반올림 (`ServerUsageController.php:467-468`).
- Description: ITSM 설명을 표시명 -> 기술 이름 순으로 찾고, 없으면 Zabbix 설명 (`:457-459`).
- 정렬: `avg` 는 숫자 비교(같으면 이름), `name` 은 `CArrayHelper::sort` (`:355-375`).

### 3.4 Zabbix 기본 기능 기준인지

- 기본 그대로: trends / trends_uint 의 시간별 요약값(`value_avg`, `value_max`), 아이템 키, 호스트 권한.
- 커스텀: 사용률로 볼 아이템 키 목록, 판정 기준 4개, 업무시간·업무일, "업무시간 Peak = 하루 전체 최대" 규칙, 하루 평균의 평균이라는 집계 방식.

### 3.5 5버전과 다른 데이터 출처

- 5버전은 하루 요약을 쌓아 둔 별도 표 `extends_trends_day` 를 읽었다. 7버전은 `trends`, `trends_uint` 를 직접 집계한다.

- 표: `value_type` 0 은 `history`, 3 은 `history_uint`. 그 밖의 형식은 뺀다 (`UsageExportService.php:179`, `:227-230`).

- CLOCK 은 `date('Y-m-d H:i:s')` (사용자 시간대).
- 이력 보관 기간보다 오래된 구간은 표에 값이 없어 나오지 않는다.

### 8.4 Zabbix 기본 기능 기준인지

- 5버전 CSV 는 `items` 와 `hosts` 를 SQL 로 묶어 이름 **완전 일치**로 찾았다. 7버전은 `host.get`, `item.get` 의 패턴 검색이다.
- 데이터 셋을 5버전은 저장하지 않았다. 7버전은 프로파일에 저장한다.

### 10.3 판정·계산 기준

- 기준 시각 = `time() - inactive_days x 86400` (`:326`).
- 미접속: 그 시각보다 **뒤**(`>`)의 `sessions.lastaccess` 가 하나도 없는 계정. 세션이 아예 없는 계정도 들어간다.
- `exclude_userids` 의 계정은 뺀다.
- "방금 만든 계정" 처리 (`auditlog` 에서 `action = CAudit::ACTION_ADD(0)`, `resourcetype = CAudit::RESOURCE_USER(0)`, `auditlog.resourceid` 와 `users.userid` 를 비교. 5버전은 `resourcename` 과 이름을 비교했다. 2026-11-24 변경)

  | `created_check` | 조건 |
  |---|---|
  | `required` | `EXISTS (그 계정의 추가 기록 중 clock < 기준 시각)` |
  | `exclude_recent` (기본) | `NOT EXISTS (그 계정의 추가 기록 중 clock >= 기준 시각)` |
  | `none` | 조건 없음 |

- 유저 종류: 역할(`role.type`). 역할이 없으면 종류 없음(`-`)이고 종류 필터에 걸리지 않는다. 종류 필터는 PHP 에서 거른다.
- 그룹: 이름 순. 그룹 편집 링크, GUI 접근 막힘/비활성이면 빨강 아니면 초록, `MAX_IN_TABLE` 개를 넘으면 "…" (5버전과 같다).
- 최근접속일시: `MAX(sessions.lastaccess)` 를 `zbx_date2str(DATE_TIME_FORMAT_SECONDS)`. 기록 없으면 `-`.
- 경고 1: `created_check` 가 `none` 이 아니고, 감사 로그 하우스키핑이 켜져 있고(`HK_AUDIT_MODE = 1`), 보관 기간 < `inactive_days` 면 화면에 경고.
- 경고 2: 세션 하우스키핑이 켜져 있고 세션 보관 기간 < `inactive_days` 면 경고 (최근 접속자가 미접속으로 나올 수 있음).

### 10.4 Zabbix 기본 기능 기준인지

- 기본 그대로: `sessions.lastaccess` (코어 유저 목록도 같은 값), 유저 역할의 type, 유저 그룹, 하우스키핑 설정, `CAudit` 상수.
- 커스텀: 감사 로그의 "유저 추가" 기록을 계정 생성일로 해석하는 규칙, 60일 기준, 제외 계정.

### 10.5 5버전과 다른 데이터 출처

- 로그인 이름이 `users.alias` 에서 `users.username` 으로, 유저 종류가 `users.type` 에서 역할의 `type` 으로 바뀌었다.
- 감사 로그 조건이 5버전은 "기준 전 추가 기록이 있어야 함"(`required`), 7버전 기본은 "최근 추가 기록이 없으면 됨"(`exclude_recent`).
- 5버전 필터는 코어 유저 화면 키(`web.user.filter*`)를 같이 썼다. 7버전은 `web.dmove.userunconnect.*`.
