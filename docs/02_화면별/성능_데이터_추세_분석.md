# 성능 데이터 추세 분석 (`perftrend.list`)

## 1. 한눈에

| 항목 | 내용 |
|---|---|
| 메뉴 위치 | 보고서 > 성능 데이터 추세 분석 (`Module.php` 의 `REPORT_MENUS`) |
| 주소 | 화면 `zabbix.php?action=perftrend.list`, 그래프 `perftrend.graph`(JSON), CSV `perftrend.export`(POST) |
| 상태 | 화면을 5버전 화면 기록(5.0 그래프 위젯 설정 화면)과 같은 모양으로 다시 만듦 (2026-11-25). CSV 아이템 규칙은 5버전 `data.analysis.js` 일부를 받아야 확정 |
| 5버전 액션 | `data.analysis` (CSV `data.analysis.csv`) |
| 내보내기 | [CSV 내보내기]. 화면의 값을 그대로 보낸다 (5버전 `excelDownloadForm` 과 같은 방식). 5버전과 같은 열 구성 |
| 권한 | 로그인한 사용자(게스트 제외). 그래프와 CSV 에는 볼 수 있는 호스트의 아이템만 나온다 |
| 설정 파일 | `conf/perftrend.conf.php` (CSV 줄 수 한도) |

## 2. 이 화면은 무엇을 하나

여러 서버의 성능 값(CPU, 메모리 등)을 **한 그래프에 겹쳐 그려** 기간에 따른 추세를 비교한다.
"데이터 셋" 한 줄이 그래프의 한 묶음이다. 줄마다 호스트 패턴과 아이템 패턴으로 아이템을 고르고, 색, 그래프 형식, Y축, 타임 시프트, 집계 등을 정한다.
값을 바꾸면 바로 그래프가 다시 그려진다. [CSV 내보내기] 로 그래프에 나온 아이템의 값을 파일로 받는다.

```

│ ■ Zabbix server: CPU utilization   ■ web-01: CPU utilization  (범례)          │
└──────────────────────────────────────────────────────────────────────────────┘
 데이터 셋 | 기간
 데이터 셋  ⋮ ■ [Zabbix server ×   ][선택]   [CPU* ×          ][선택]   ×
            ⋮ ■ [web-*  ×          ][선택]   [Memory* ×       ][선택]   ×   <- 펼친 줄
                기본 색상 ■                      결손 데이터 [없음|접속됨|0 으로 처리]
                그래프 형식 [선|포인트|계단|막대 그래프]  Y축 [왼쪽|오른쪽]
                너비 ──●── 1                       타임 시프트 [없음]
                포인트 사이즈 ──●── 3                Aggregation function [없음 ▼]
                투명도 ──●── 5                      Aggregation interval [1h]
                채우기 ──●── 3                      Aggregate [Each item|데이터 셋]
            [+ 새로운 데이터 셋을 추가]
```

- 5버전 화면 기록(`v5_restored/screens_old.md` 8번)과 같은 배치, 같은 항목, 같은 기본값이다.
- 줄을 누르면 그 줄만 펼쳐진다. 손잡이(⋮)로 순서를 바꾼다. 데이터 셋은 최대 10줄. 다 지우면 빈 줄 하나가 남는다.
- 그래프 형식에 따라 못 쓰는 옵션은 흐려진다 (포인트: 너비/채우기/결손 데이터, 막대: 너비/채우기/결손 데이터/포인트 사이즈, 선·계단: 포인트 사이즈). 집계 함수가 "없음" 이면 Aggregation interval, Aggregate 가 흐려진다.
- [기간] 탭: [사용자 정의 기간 설정] 을 체크하면 시작/종료(날짜 또는 `now-1d` 같은 표현)를 쓴다. 체크하지 않으면 최신 1시간.
- 호스트/아이템 패턴 칸은 코어 그래프 위젯과 같은 부품이다. 글자를 쳐서 패턴(`*` 사용)을 넣거나 [선택] 으로 목록에서 고른다.

## 4. 어떻게 만들었나 (동작 순서)

1. **화면** (`perftrend.list`) - 저장된 데이터 셋과 기간으로 폼을 그린다. 그래프 칸은 비워 둔다.
2. **그래프** (`perftrend.graph`) - 스크립트가 처음 열 때와 값이 바뀔 때마다 폼의 값과 그래프 칸의 너비를 POST 로 보낸다.
   1. `PerfTrendService::normalizeDataSets()` 로 값을 고르고(틀린 값은 기본값), 프로파일 `web.dmove.perftrend.datasets`, `web.dmove.perftrend.period` 에 JSON 으로 저장한다.
   2. `resolvePeriod()` 로 기간을 초로 바꾼다. 틀리면 최신 1시간으로 그리고 노란 안내를 띄운다.
   3. `buildGraph()` 가 코어 그래프 위젯의 그리기 함수 `CSvgGraphHelper::get()` 을 부른다. 응답은 SVG, 범례, 말풍선용 값(그래프 크기 등).
   4. 스크립트가 그래프를 넣고, 코어 `class.csvggraph.js` 로 값 말풍선을 붙인다.
3. **CSV** (`perftrend.export`) - 스크립트가 폼의 값을 그대로 POST 로 보낸다. 저장한 뒤:
   1. `resolveItems()`: 그래프와 같은 규칙으로 아이템을 찾는다. 호스트 패턴은 호스트 표시 이름, 아이템 패턴은 매크로를 푼 아이템 이름에서 찾고, `*` 는 아무 글자다. 숫자 아이템(소수, 정수)만. API 로 찾으므로 볼 수 있는 호스트만 나온다.
   2. 기간이 틀리거나 아이템이 없으면 화면으로 돌아가 이유를 띄운다.
   3. `countCsvRows()`: 줄 수를 세고 한도(`max_csv_rows`, 기본 100만)를 넘으면 화면으로 돌아가 이유를 띄운다.
   4. `buildCsv()`: 기간이 **2시간 미만이면 원본값**(`history`, `history_uint`), **2시간 이상이면 1시간 요약값**(`trends`, `trends_uint`). 아이템마다 [제목 줄 + 값 줄 + 빈 줄]. 파일명 `data_history_날짜_시각.csv` 또는 `data_trends_...`.

CSV 열 (5버전과 같다):

| 종류 | 열 |
|---|---|
| 원본값 | `"HOST","ITEM","수집시간","값(value)"` |
| 요약값 | `"HOST","ITEM","집계시간","최소","평균","최대"` |

## 5. 5버전과 비교

| 항목 | 5버전 | 7버전 | 이유 |
|---|---|---|---|
| 화면 모양 | 5.0 그래프 위젯 설정 화면 (그래프 위, [데이터 셋] [기간] 탭 아래) | 같음 | |
| 데이터 셋 옵션 | 색, 형식, 너비, 포인트 사이즈, 투명도, 채우기, 결손 데이터, Y축, 타임 시프트, 집계 | 같음 | |
| 그래프 형식 글자 | 선 / 포인트 / 막대 그래프 / Bar | 선 / 포인트 / 계단 / 막대 그래프 | 5.0 번역이 계단(Staircase)을 "막대 그래프" 로 잘못 적었다. 뜻에 맞게 고침 |
| 그래프 그리기 | 5.0 대시보드 위젯 코드를 복사 | 7.0 코어 그래프 그리기 함수 | 7.0 은 대시보드 구조가 바뀌어 5.0 코드가 돌지 않는다 |
| 다시 그리기 | 값을 바꾸면 바로 (위젯 설정 미리보기) | 같음 | |
| 기간 | [기간] 탭 (사용자 정의 기간 설정 + 시작/종료), 아니면 대시보드 기간(기본 최신 1시간) | [기간] 탭, 아니면 최신 1시간 | 이 화면에는 대시보드가 없다 |
| 값 저장 | 매번 빈 화면에서 시작 | 사용자별로 저장 | 다시 들어와도 같은 그래프 |
| CSV 보내기 | 화면 값을 `jsonStr` 하나로 POST | 화면 값을 폼 그대로 POST | 결과 같음 |
| CSV 아이템 찾기 | 호스트 이름(`h.host`), 아이템 이름을 **완전 일치**(SQL `IN`) | 그래프와 같은 **패턴** 규칙 | `data.analysis.js` 가 패턴을 이름 목록으로 바꿨는지 확인 전. 받으면 맞춘다 |
| CSV 권한 | 검사 없음. DB 를 바로 읽음 | API 로 찾아 볼 수 있는 호스트만 | 권한 밖 호스트의 값이 나가던 문제 |
| CSV SQL | 호스트/아이템 이름과 기간을 SQL 에 이어 붙임 | 아이템 ID 와 정수만 | SQL 인젝션 |
| CSV 줄 수 | 한도 없음 | 100만 줄 (설정) | 서버 메모리 |
| 원본/요약 기준 | 2시간 미만 / 이상 | 같음 | |
| CSV 열 | 위 표 | 같음 | |

## 9. 확인 방법

### 테스트 환경 (http://127.0.0.1:18970)

2026-11-25 화면을 다시 만든 뒤 헤드리스 크롬으로 실제로 눌러 보며 확인했다.

1. 데이터 셋 3줄 (선 / 막대 그래프 + Y축 오른쪽 / 포인트 + avg 10m 집계), 기간 최신 3시간: 선 78개, 포인트, 막대가 그려진다. 오른쪽 세로축이 나온다.
2. 화면 모양: 그래프 위, [데이터 셋] [기간] 탭, 줄 머리(손잡이, 색, 호스트 패턴+선택, 아이템 패턴+선택, ×), 펼친 줄의 옵션 두 열이 5버전 화면 기록과 같다.
3. 줄 누르기로 펼치기, [+ 새로운 데이터 셋을 추가](다음 색 자동), × 로 지우기, 형식을 막대로 바꾸면 결손 데이터가 흐려짐: 모두 동작. 값을 바꿀 때마다 그래프가 다시 그려진다.
4. 그래프 위에 마우스: 시각과 아이템별 값 말풍선이 뜬다.
5. [기간] 탭: 체크 전에는 시작/종료가 막혀 있고, 체크 후 `now-6h` 를 넣으면 6시간 그래프로 바뀐다. 시작 > 종료면 노란 안내 "시작이 종료보다 앞이어야 합니다." 와 함께 최신 1시간으로 그린다.
6. [CSV 내보내기] (30분): `data_history_...csv`, 머리 줄 `"HOST","ITEM","수집시간","값(value)"`. 시작 > 종료면 화면으로 돌아와 이유를 띄운다.

### 고객환경에서 5버전과 비교

같은 데이터 셋(호스트/아이템 이름)과 같은 기간으로 5버전 CSV 와 7버전 CSV 를 받아 줄 수와 값을 비교한다. 5버전은 이름 완전 일치라, 7버전에 패턴(`*`)을 쓰면 아이템이 더 많이 나올 수 있다.

### 그대로는 돌지 않는 곳 (7.0 에서 바뀜)

1. **대시보드 자바스크립트가 없다.** `data.analysis.js` 는 5.0 의 jQuery `dashboardGrid` 플러그인 복사본이다. 7.0 은 대시보드를 새로 만들어 `class.dashboard.grid.js` 가 없고(`class.dashboard.js`, `class.dashboard.page.js` 로 바뀜) 위젯도 jQuery 플러그인이 아니다. 그래프 컨트롤러의 인라인 스크립트도 `jQuery(".dashbrd-grid-container").dashboardGrid(...)` 를 부른다. 이 부분은 7.0 방식으로 다시 써야 한다.
2. **그래프 위젯 컨트롤러가 바뀌었다.** 5.0 `CControllerWidgetSvgGraphView` 는 7.0 에서 위젯 모듈(`ui/widgets/svggraph/actions/WidgetView.php`, 부모 `CControllerDashboardWidgetView`)로 옮겨졌다. 입력 이름, 폼 클래스(`CWidgetForm...`)가 다르다. 5버전 컨트롤러를 복사하면 클래스가 없어 오류가 난다.
3. **그래프 그리기 함수의 인자가 다르다.** 이름은 같은 `CSvgGraphHelper::get($options, $width, $height)` 이지만 7.0 은 `$options` 의 구성(데이터 셋, 표시 옵션, 축, `time_period` 등)이 다르다. 5버전이 만든 `$graph_data` 를 그대로 넘기면 안 된다.
4. **그래프 말풍선 스크립트.** 5버전은 `jQuery(...).svggraph(...)` 를 썼다. 7.0 에서도 `js/class.csvggraph.js` 가 있지만 위젯 객체를 받는 방식이 바뀌어 5버전 호출 그대로는 맞지 않는다.

### 5버전 코드의 문제 (가져오면서 고칠 것)

5. **응답 값 오류.** 그래프 컨트롤러가 `'script_inline' => $graph_data` 로 스크립트 문자열이 아니라 배열을 넘긴다. 5버전에서도 스크립트가 제대로 안 갔을 수 있다.
6. **그래프 ID 고정.** `uniqueid` 가 `'SVGID'` 로 고정이라 한 화면에 그래프가 하나만 된다.
7. **기간이 대시보드와 섞인다.** 기간을 대시보드의 저장 이름(`web.dashbrd.filter`)으로 읽는다. 이 화면에서 기간을 바꾸면 대시보드 기간도 바뀐다. 이 화면 전용 이름을 쓴다 (지금 임시 구현은 `web.dmove.perftrend.filter`).
8. **CSV 의 보안 문제** (5버전 CSV 컨트롤러 기준. CSV 뷰 파일은 아직 없음): 호스트/아이템 이름과 기간을 SQL 에 글자로 이어 붙인다(SQL 인젝션). 사용자 권한 검사 없이 DB 를 바로 읽어 권한 밖 호스트 값도 나간다. 줄 수 한도가 없다. 가져올 때 이 세 가지는 막는다 (지금 임시 구현은 막혀 있음).
9. **CSV 아이템 규칙.** 화면은 패턴(`*`)인데 5버전 CSV 는 이름 완전 일치(`IN`)였다. 그래프와 CSV 의 아이템이 다를 수 있다. 5버전대로 둘지 정해야 한다.

### 옮기는 방법

10. **코어 파일을 고치지 않는다.** 5버전은 코어 폴더(`app/controllers`, `app/views`, `js`)에 파일을 넣었다. 7.0 은 모듈(`ui/modules/dmove`) 안에 넣는다. 액션 이름은 `perftrend.list` / `perftrend.export` 를 그대로 쓰고, 화면 구성과 동작만 5버전에 맞춘다.
11. 화면 모양(그래프 위, [데이터 셋] [기간] 탭 아래, 데이터 셋 줄의 항목)은 지금 임시 구현이 이미 5버전과 같다. 그래서 실제로 바뀌는 곳은 데이터 셋 세부 옵션(너비, 투명도, Y축, 타임 시프트, 집계 등), 그래프 말풍선, CSV 규칙이다.
12. 빠진 파일 3개(`monitoring.data.analysis.csv.php`, `monitoring.widget.svggraph.view.php`, `csvggraphwidget.js`)와 `data.analysis.js` 나머지 없이 시작하면, 그 부분은 추정으로 만들게 된다.
