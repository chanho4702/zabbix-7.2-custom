# 성능 데이터 추세 분석 (`perftrend.list`)

## 1. 한눈에

| 항목 | 내용 |
|---|---|
| 메뉴 위치 | 보고서 > 성능 데이터 추세 분석 (`Module.php` 의 `REPORT_MENUS`) |
| 주소 | 화면 `zabbix.php?action=perftrend.list`, CSV `zabbix.php?action=perftrend.export&format=csv` |
| 상태 | **임시 구현** (2026-11-23). 5버전과 다른 점이 많아 5버전 파일을 받은 뒤 다시 만들기로 함 (2026-11-24). 필요한 파일: 미구현 목록 "아직 필요한 것" |
| 5버전 액션 | `data.analysis` (CSV `data.analysis.csv`) |
| 내보내기 | [CSV 내보내기]. 5버전과 같은 열 구성 |
| 권한 | 로그인한 사용자(게스트 제외). 그래프와 CSV 에는 볼 수 있는 호스트의 아이템만 나온다 |
| 설정 파일 | `conf/perftrend.conf.php` (CSV 줄 수 한도) |

## 2. 이 화면은 무엇을 하나

여러 서버의 성능 값(CPU, 메모리 등)을 **한 그래프에 겹쳐 그려** 기간에 따른 추세를 비교한다.
"데이터 셋" 한 줄이 그래프의 한 묶음이다. 줄마다 호스트 패턴과 아이템 패턴으로 아이템을 고르고, 색과 그래프 형식을 정한다.
[CSV 내보내기] 로 그래프에 나온 아이템의 값을 파일로 받는다.

## 3. 화면 구성

```
성능 데이터 추세 분석                                              [CSV 내보내기]
┌──────────────────────────────────────────────────────────────────────────┐
│  (그래프. 가로축 시간, 세로축 값과 단위)                                    │
│  ■ Zabbix server: CPU utilization   ■ web-01: CPU utilization  (범례)     │
└──────────────────────────────────────────────────────────────────────────┘
                                         [데이터 셋]  < 줌 아웃 >  [최신 1 시간]
     호스트 패턴          아이템 패턴           그래프 형식
 [■] [web-*, db-01    ] [CPU utilization  ] [선      ▼]  삭제
 [■] [Zabbix*         ] [Memory*          ] [막대 그래프▼] 삭제
 + 새로운 데이터 셋을 추가
 여러 개는 쉼표로 나눕니다. * 는 아무 글자를 뜻합니다. 예) web-*, db-01
                               [적용] [리셋]
```

- 5버전처럼 그래프가 위, 탭 [데이터 셋] [기간] 이 아래다. 기간은 코어의 시간 선택기다.
- [적용] 을 누르면 데이터 셋이 사용자별로 저장되고 그래프가 다시 그려진다. [리셋] 은 데이터 셋을 지운다.
- 데이터 셋은 최대 10줄. 줄을 다 지우면 빈 줄 하나가 남는다.
- 그래프 형식: 선 / 포인트 / 계단 / 막대 그래프.
- 데이터 셋이 비어 있으면 그래프 자리에 "데이터 셋에 호스트 패턴과 아이템 패턴을 넣고 [적용] 을 누르세요." 가 나온다.

## 4. 어떻게 만들었나 (동작 순서)

1. **기간** - 코어 시간 선택기. 프로파일 `web.dmove.perftrend.filter` 에 저장된다. 기본은 최신 1시간.
2. **데이터 셋 저장** - [적용] 이면 `ds[n][hosts|items|color|type]` 을 `PerfTrendService::normalizeDataSets()` 로 정리해 프로파일 `web.dmove.perftrend.datasets` 에 JSON 으로 저장한다. 색이 잘못되면 코어 기본 색상표에서, 형식이 잘못되면 "선" 으로 바꾼다.
3. **그래프** - `PerfTrendService::buildGraph()` 가 코어 그래프 위젯의 그리기 함수 `CSvgGraphHelper::get()` 을 부른다. 데이터 셋의 나머지 옵션(너비 1, 투명도 5, 채우기 3, 결손 데이터 없음, Y축 왼쪽, 집계 없음)은 코어 기본값이다. 크기는 1200 x 400.
4. **CSV** (`perftrend.export`)
   1. `resolveItems()`: 그래프와 같은 규칙으로 아이템을 찾는다. 호스트 패턴은 호스트 표시 이름, 아이템 패턴은 매크로를 푼 아이템 이름에서 찾고, `*` 는 아무 글자다. 숫자 아이템(소수, 정수)만. API 로 찾으므로 볼 수 있는 호스트만 나온다.
   2. 아이템이 없으면 화면으로 돌아가 "데이터 셋에 맞는 아이템이 없습니다." 를 띄운다.
   3. `countCsvRows()`: 줄 수를 세고 한도(`max_csv_rows`, 기본 100만)를 넘으면 화면으로 돌아가 이유를 띄운다.
   4. `buildCsv()`: 기간이 **2시간 미만이면 원본값**(`history`, `history_uint`), **2시간 이상이면 1시간 요약값**(`trends`, `trends_uint`). 아이템마다 [제목 줄 + 값 줄 + 빈 줄]. 파일명 `data_history_날짜_시각.csv` 또는 `data_trends_...`.

CSV 열 (5버전과 같다):

| 종류 | 열 |
|---|---|
| 원본값 | `"HOST","ITEM","수집시간","값(value)"` |
| 요약값 | `"HOST","ITEM","집계시간","최소","평균","최대"` |

## 5. 5버전과 비교

| 항목 | 5버전 | 7버전 | 이유 |
|---|---|---|---|
| 그래프 | 5.0 대시보드 그래프 위젯 코드를 복사한 화면에 빈 대시보드를 띄움 | 7.0 코어 그래프 그리기 함수(`CSvgGraphHelper::get`)를 그대로 부름 | 코드를 복사하지 않아 Zabbix 를 올려도 따라간다 |
| 데이터 셋 옵션 | 색, 형식, 너비, 포인트 사이즈, 투명도, 채우기, 결손 데이터, Y축, 타임 시프트, 집계 | 색, 형식. 나머지는 기본값 | 5버전 화면의 값도 기본값이었다. 필요하면 늘린다 (8장) |
| 데이터 셋 저장 | 매번 빈 화면에서 시작 | 사용자별로 저장 | 다시 들어와도 같은 그래프 |
| 그래프 위 말풍선 | 있음 (위젯의 자바스크립트) | 없음 | 위젯 자바스크립트가 대시보드에 묶여 있다 (8장) |
| CSV 아이템 찾기 | 호스트 이름(`h.host`), 아이템 이름을 **완전 일치**(SQL `IN`) | 그래프와 같은 **패턴** 규칙 | 화면은 패턴인데 CSV 만 완전 일치라 그래프와 CSV 의 아이템이 달랐다 |
| CSV 권한 | 검사 없음. DB 를 바로 읽음 | API 로 찾아 볼 수 있는 호스트만 | 권한 밖 호스트의 값이 나가던 문제 |
| CSV SQL | 호스트/아이템 이름과 기간을 SQL 에 이어 붙임 | 아이템 ID 와 정수만 | SQL 인젝션 |
| CSV 줄 수 | 한도 없음 | 100만 줄 (설정) | 서버 메모리 |
| 원본/요약 기준 | 2시간 미만 / 이상 | 같음 | |
| CSV 열 | 위 표 | 같음 | |

## 7. 비어 있는 부분과 가정

| 구분 | 내용 | 확인할 것 | 고칠 곳 |
|---|---|---|---|
| 없음 | 5버전 `data.analysis.js`(화면 스크립트)를 받지 못했다. 5버전 CSV 버튼이 화면의 패턴을 이름 목록으로 바꿔 보냈는지 모른다 | 받으면 CSV 아이템 규칙 대조 | `PerfTrendService::resolveItems()` |
| 없음 | [기간] 탭의 5버전 내용은 확인 못 함. 7버전은 코어 시간 선택기 | 5버전 화면 | 뷰 |
| 다름 | 데이터 셋 세부 옵션(너비, 투명도 등)과 그래프 위 말풍선이 없다 | 필요한지 | 8장 |

## 8. 개선점

| 제안 | 효과 | 5버전과 달라지나 |
|---|---|---|
| 데이터 셋 세부 옵션(Y축, 타임 시프트, 집계) 추가 | 5버전 화면과 같은 설정 | 같아진다 |
| 그래프 위 말풍선(값 보기) | 그래프에서 바로 값을 읽는다 | 같아진다. 코어 위젯 자바스크립트를 떼어 와야 한다 |
| CSV 를 흘려보내기(사용률 추출처럼) | 100만 줄 한도를 크게 늘릴 수 있다 | 결과 같음 |

## 9. 확인 방법

### 테스트 환경 (http://127.0.0.1:18970)

2026-11-23 에 이렇게 확인했다.

1. 데이터 셋 2줄: `Zabbix server` + `History * cache*` (선), `Zabbix*` + `Configuration cache*` (막대 그래프), 기간 최신 1시간.
   - 기대: 그래프에 3개 아이템, 범례 3줄. 결과 같음.
2. [CSV 내보내기]: 파일 `data_history_...csv`, 제목 줄 3개(아이템 3개), 값 줄이 1분 간격.
3. 기간을 최신 6시간으로 바꾸고 [CSV 내보내기]: 파일 `data_trends_...csv`, 열이 집계시간/최소/평균/최대, 1시간 간격.
4. 데이터 셋을 없는 호스트(`nohost*`)로 바꾸고 [CSV 내보내기]: 화면으로 돌아와 "데이터 셋에 맞는 아이템이 없습니다."
5. 잘못된 색(`#zz`), 형식(9): 기본 색, "선" 으로 저장된다.
6. [+ 새로운 데이터 셋을 추가] 로 줄이 늘고, [삭제] 로 줄이 준다. 다 지우면 빈 줄 하나가 남는다.

### 고객환경에서 5버전과 비교

같은 데이터 셋(호스트/아이템 이름)과 같은 기간으로 5버전 CSV 와 7버전 CSV 를 받아 줄 수와 값을 비교한다. 5버전은 이름 완전 일치라, 7버전에 패턴(`*`)을 쓰면 아이템이 더 많이 나올 수 있다.
