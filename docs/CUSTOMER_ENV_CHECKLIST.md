# 고객환경에서 확인할 것

아직 확인하지 못해서 코드를 비워 두었거나 가정으로 만든 곳을 정리했다. 위에서부터 급한 순서다.

## 확인하는 방법

- 5버전 소스와 화면은 **고객환경 안에서 열어 보고**, 필요한 내용(아이템 키, 기준 값, 컬럼 구성, 처리 순서)을 파악한다.
- 고객 자료(소스 파일, 화면, 실제 서버 이름, IP, 계정, 접속 주소)는 **밖으로 가져오지 않는다.** 이 저장소에도 넣지 않는다.
- 파악한 내용은 고객환경 안에서 이 모듈 코드의 `TODO(고객환경)` 자리에 직접 채운다.
- 소스에서 `TODO(고객환경)` 를 검색하면 아래 항목이 있는 자리가 모두 나온다.

## 1. 설정 채우기 (코드는 되어 있고, 값을 넣어야 동작하는 것)

이 저장소는 공개 저장소라서 고객 환경의 값(테이블 이름, 아이템 키, 태그)은 설정 파일에 비워 두었다.
`conf/` 의 값은 5버전 소스에서 확인한 값으로 채워 두었다 (2026-11-23). 고객 서버에 올린 뒤 아래 항목이 실제와 같은지 **확인**한다. 다르면 그 파일의 값만 고친다. 확실하지 않은 값 두 개: ITSM 스키마 이름(`conf/itsm.conf.php`), 유닉스 CPU 키의 뒷부분(`conf/serverusage.conf.php`).

| # | 확인할 것 | 방법 | 맞지 않으면 | 고칠 곳 |
|---|---|---|---|---|
| 1-1 | ITSM 테이블의 스키마/테이블 이름 | `psql` 에서 `\dt *.itsm_info`. 5버전 값은 ITSM 트레잇(`...Itms.php`) 맨 위 두 줄 | SW 인벤토리가 Zabbix 호스트 기준으로만 나오고, 다른 화면의 Description 이 Zabbix 호스트 설명으로 나온다 | `conf/itsm.conf.php` |
| 1-2 | 일일점검용 트리거 태그의 이름과 항목별 값 7개. 그리고 7버전 서버의 트리거에 그 태그가 달려 있는가 | 5버전 일일점검 트레잇(`...Daily.php`)의 `$tag_*` 값. 서버에서는 데이터 수집 > 호스트(또는 템플릿) > 트리거의 태그 | 설정이 비어 있으면 일일점검에 '-' 와 설정 안내가 나온다. 태그가 달린 트리거가 없으면 점검대상 0 으로 나온다 | `conf/dailycheck.conf.php`, 서버의 트리거/템플릿 |
| 1-3 | CPU 사용률 아이템 키 3종 (리눅스, 유닉스, 윈도우) | 5버전 키 클래스(`...Key.php`)의 `serverCpuUsage()`. 서버에서는 종류별 호스트 하나씩 아이템 목록의 키 | 설정이 비어 있으면 저사용/고사용 서버 화면과 CPU Top 10 팝업에 설정 안내가 나온다. 키가 다르면 호스트가 안 나온다 | `conf/serverusage.conf.php` 의 `cpu_item_keys` |
| 1-3b | 메모리 사용률 아이템 키 (유닉스, 윈도우 등) | 5버전 키 클래스의 `serverMemoryUsage()`. 서버에서는 종류별 호스트의 아이템 목록의 키. 값이 0~100 의 사용률(%)인지도 본다 | 설정이 비어 있으면 일일점검의 [Memory 사용률 Top 10] 팝업에 설정 안내가 나온다 | `conf/serverusage.conf.php` 의 `memory_item_keys` |
| 1-7 | 장기 미접속 기준: 일수, 만든 날짜 확인 여부, 제외 계정 | 기본값(60일, 확인함, userid 1 제외)이 5버전과 같다. 정책이 다르면 바꾼다 | 기준이 다르면 목록이 달라진다 | `conf/userunconnect.conf.php` |
| 1-8 | 감사 로그 보관 기간이 장기 미접속 기준 일수(60일)보다 긴가 | 관리 > 하우스키핑 > 감사. 7.0 기본값은 31일이다 | 짧으면 장기 미접속 계정 목록이 비고 화면에 경고가 나온다. 보관 기간을 늘리거나 `created_check` 를 `'exclude_recent'` 로 바꾼다 | 서버의 하우스키핑 설정 또는 `conf/userunconnect.conf.php` |
| 1-8b | (검증) 감사 로그에 유저 추가 기록이 없는 계정이 있는가. 장기 미접속 계정 화면은 2026-11-23 부터 기록이 없는 계정도 보여 주도록 정했다 (`created_check = 'exclude_recent'`) | `conf/userunconnect.conf.php` 주석의 확인 쿼리 3개. 기록이 모두 남아 있으면 5버전 방식과 결과가 같다 | 5버전과 똑같은 목록이 필요하면 `created_check` 를 `'required'` 로 |
| 1-9 | CPU/메모리 아이템의 이력(history) 보관 기간 (**필수 확인**) | 데이터 수집 > 호스트 > 아이템 > 그 아이템의 "이력 보관 기간". 관리 > 하우스키핑의 이력 전체 설정도 본다 | CPU/Memory 추출은 이력 표에서 수집 값 원본을 읽는다 (2026-11-23 구현). 받으려는 기간(최대 3개월)보다 보관 기간이 짧으면 그 구간은 파일에 나오지 않는다. 짧으면 아이템(또는 템플릿)의 이력 보관 기간을 늘린다 | 아이템 설정 (코드 아님). `pages/usageexport.md` 7장 |
| 1-10 | CPU/Memory 추출의 최대 기간(93일), 줄 수 한도(1000만), 줄 수 어림용 수집 간격(180초), 업무시간(9~18시) | 기본값은 5버전 소스와 화면 안내문의 값이다. 실제 수집 간격이 3분이 아니면 `assumed_interval` 을 바꾼다 | 수집 간격이 더 짧으면 실제 줄 수가 어림보다 많아진다 | `conf/usageexport.conf.php` |
| 1-4 | 윈도우 패치 목록 파일 아이템 키 | 5버전 키 클래스의 `patchFile()`. 서버에서는 윈도우 호스트의 아이템 목록의 키 | 설정이 비어 있으면 윈도우즈 패치 현황에 설정 안내가 나온다. 키가 다르면 호스트가 안 나온다 | `conf/winpatch.conf.php` |
| 1-5 | 패치 목록 파일의 형식 (첫 줄이 `Caption CSName Description ...` 인 칸 맞춤 표인가) | 최신 데이터 화면에서 그 아이템의 값을 열어 본다 | 상세보기 표의 열이 어긋난다 | `includes/WinPatchService.php` 의 `parse()` |
| 1-6 | 인벤토리 필드 `os`, `software_app_a~d` 에 값이 들어 있는가 | 호스트의 인벤토리 탭 | SW 인벤토리의 OS/WEB/WAS/DB/이중화가 빈칸으로 나온다 | 서버의 인벤토리 수집 설정, 또는 `includes/SoftwareResolver.php` |

같은 조건으로 5버전 화면과 7버전 화면을 나란히 열어 숫자와 목록을 비교한다.
